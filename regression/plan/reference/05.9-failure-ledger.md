# 5.9 Failure ledger (record failures, do not auto-fix)

> Part of the [regression plan](../README.md). Section numbers (§5.9, §6.U, D12, …) are global across the plan; the README's section map says which file holds each one.


**Problem.** When an agent runs tests and sees a failure, it starts editing code or tests to make the failure go away. That has three costs: the agent drifts off its actual task, the "fix" is often a weakened assertion, and the failure is gone before the owner has seen it. The owner wants every failure from every tier written to a run file, to be fixed later on purpose.

**First principles.**

- An agent learns about a failure from the command's output. If that output only says "N failed", the default move is to investigate and fix. If the output also says where the failure was recorded and that fixing it is out of scope, the agent has an explicit instruction instead of an implied task.
- Instructions alone are not reliable for agents. So the policy is delivered three ways: the test run's own output, an always-on agent rule, and a Cursor hook that attaches the instruction to the tool result.
- Recording must never change the result. The exit code, pre-commit, pre-push and CI gates stay exactly as strict as they are; the ledger is a side channel. (Making failures "pass" so the agent does not notice them would also hide them from the gates.)
- A record is only useful later if it is self-contained: what failed, at which tier, on which commit, the error, and the exact command to reproduce it. The owner (or a fix agent launched on purpose) should not need to rerun the whole suite to start.
- Runs get killed (Ctrl-C, timeouts, a crashed live agent). Records written only at the end would be lost, so each failure is appended as soon as it is reported.

## 5.9.1 What gets recorded

Every failure from any of these, in any tier:

| Source | Mechanism |
|---|---|
| `pytest` anywhere in this repo (`tests/`, `regression/` incl. `--live`, `regression/selftest/`) | pytest plugin `testkit/failure_ledger.py`, always loaded through `pytest.ini` `addopts = -p testkit.failure_ledger` |
| `python -m regression.t4` and `python -m regression.t5` (not pytest) | The runners call the same `LedgerWriter` API directly: one record per failed scenario, per failed assertion group, per failed trial verdict, and per runner crash |
| `cli/tests`, `integrations/browser-mcp/tests` (own projects) | `scripts/ci-local.sh` passes `-p testkit.failure_ledger` with the repo root on `PYTHONPATH`, so their failures land in the same run group. This is why the plugin and `testkit/scrub.py` must stay stdlib-only. |

Recorded outcomes: test failure (setup, call, teardown phases), error, collection error (`pytest_collectreport`), strict `xpass`, internal error, T4 scenario failure, T5 regression verdict (`fail`; `warn` is recorded with `severity: warn`), and a session that ended without its end record (detected and marked `incomplete` by the next run). Skips and non-strict xfails are not failures and are not recorded.

## 5.9.2 Where it is written

```text
test-runs/                                  # repo root, gitignored; CI uploads it as an artifact
  20261025T153012Z-3f2a9c1-48211.jsonl      # one file per run (= one pytest or runner invocation)
  20261025T153012Z-3f2a9c1-48211.outcomes.tsv.gz   # nodeid<TAB>outcome for every test run, used to decide what is still open
  LATEST.json                               # pointer to the newest run + its counts (read by the hook)
  index.jsonl                               # one summary line per run, newest last
  triage.json                               # owner's status per failure fingerprint (5.9.5)
```

- Run id: `<UTC start>-<git sha7>-<pid>`. A `MONKEYBOT_TEST_RUN_GROUP` env var (set by `ci-local.sh`, the pre-push hook, and CI) ties together the separate invocations of one gate run.
- Under xdist, only the controller process writes (workers forward their reports to it already); this avoids interleaved lines.
- Each line is appended and flushed as soon as the report arrives.
- `--ledger-dir PATH` overrides the location; `--no-ledger` (or `MONKEYBOT_TEST_LEDGER=0`) turns it off for one run. It is on by default, including in CI.
- Retention: at run start, delete a run only if it is outside the newest 200 runs **and** older than 30 days. Override with `MONKEYBOT_TEST_LEDGER_KEEP` and `MONKEYBOT_TEST_LEDGER_DAYS`. Pruning touches only top-level `*.jsonl` and `*.outcomes.tsv.gz` run files (never `index.jsonl`, subfolders such as `phase0a/`, or `triage.json`).
- `LATEST.json` is `{"run_id", "path", "finished_at", "complete", "counts"}` for the newest run; an `index.jsonl` line is that run's `run_end` object plus `path`.
- `trigger` is `MONKEYBOT_TEST_TRIGGER`: one of `manual`, `pre-commit`, `pre-push`, `ci`; default `manual`.

## 5.9.3 Record format

One JSON object per line. The first line is the run header, the last is the run footer, everything between is a failure.

```json
{"kind": "run_start", "schema_version": 1, "run_id": "20261025T153012Z-3f2a9c1-48211", "group": "pre-push-20261025T153010Z",
 "started_at": "2026-10-25T15:30:12Z", "git": {"sha": "3f2a9c1...", "branch": "develop", "dirty": true},
 "trigger": "pre-push", "argv": ["pytest", "tests", "regression", "-m", "t1 or t2 or t3", "-n", "auto"],
 "markexpr": "t1 or t2 or t3", "python": "3.12.7", "platform": "darwin-arm64", "workers": 10,
 "live": null}

{"kind": "failure", "run_id": "...", "seq": 1, "severity": "fail",
 "tier": "t2", "case": "T2-LOOP-07", "area": "LOOP",
 "nodeid": "regression/t2/loop/scenarios/loop/doom_identical_read.yaml::doom_identical_read",
 "path": "regression/t2/loop/scenarios/loop/doom_identical_read.yaml", "line": null,
 "phase": "call", "outcome": "failed", "duration_s": 0.41, "worker": "gw3",
 "exc_type": "AssertionError",
 "message": "interventions: expected [doom_loop], got []",
 "traceback": "<scrubbed, capped at 16 KB>",
 "captured": {"stdout": "<tail 4 KB>", "stderr": "<tail 4 KB>", "log": "<tail 4 KB>"},
 "scenario": {"mode": "scripted", "driver": "loop"},
 "artifacts": ["regression/t4/runs/<id>/run.json", "/tmp/.../transcript.ndjson"],
 "repro": "uv run pytest 'regression/t2/loop/scenarios/loop/doom_identical_read.yaml::doom_identical_read' -p no:xdist",
 "fingerprint": "sha1(nodeid | exc_type | normalized message | top in-repo frame)[:12]",
 "catalog_expect": "Three identical read_file calls: doom_loop; next provider request has empty tools; recovery note in system text."}

{"kind": "run_end", "run_id": "...", "finished_at": "2026-10-25T15:33:40Z", "exit_status": 1, "complete": true,
 "counts": {"passed": 3912, "failed": 3, "errors": 1, "skipped": 41, "xfailed": 2, "xpassed_strict": 0}}
```

Field rules:

- `tier` comes from the item's tier marker (section 5.6); `case` from the YAML `case:` key or `@pytest.mark.case("T1-GW-01")`; both may be `null` for an existing unit test that has no case ID yet.
- `live` (header) and per-failure `live` / `trials` blocks are filled by T4/T5: provider, model, agent URL, judge scores, `k/N`, baseline `k/N`, verdict.
- `message`, `traceback` and `captured` go through `testkit/scrub.py` (the same scrubber the cassette recorders use: `Authorization`, `x-api-key`, `x-goog-api-key`, `sk-`, `nvapi-`, bearer tokens, project ids) and are size-capped.
- `area` is the middle part of `case` (`T2-LOOP-07` → `LOOP`), else `null`.
- `fingerprint` deliberately ignores line numbers, temp paths, timestamps and ids, so the same bug across many runs collapses to one entry. The normalized message replaces hex ids, digit runs and temp paths with placeholders; the top in-repo frame is the deepest traceback frame under the repo root, written `path:function`.
- `catalog_expect` is copied from the case's row in `docs/testing.md` (5.10), so the record states what *should* have happened without opening another file.

## 5.9.4 What the agent sees

1. **End-of-run banner** printed by the plugin (and the T4/T5 runners) whenever at least one failure was recorded:

```text
==================== monkeybot failure ledger ====================
4 failures recorded to test-runs/20261025T153012Z-3f2a9c1-48211.jsonl
  T2-LOOP-07  regression/t2/loop/scenarios/loop/doom_identical_read.yaml   AssertionError
  T1-GW-01    tests/contracts/test_sse_schema.py::test_every_kind           ValidationError
  ...
These failures are recorded for later triage. Agents: do not change code or
tests to fix them in this task. Report the run file and continue (docs/testing.md §5).
Inspect: uv run python -m testkit.failures latest
=================================================================
```

2. **Always-on agent rule** `.cursor/rules/test-failures.mdc` (`alwaysApply: true`), short:
   - A failing test, scenario, or trial is a finding to report, not a task. Do not edit source, tests, scenarios, goldens, cassettes, or baselines to make it pass.
   - Do not skip, quarantine, `xfail`, delete, or loosen a check to make a run green.
   - In the reply, list the run file and each failure's case id, path, and one-line error. Then continue the original task, or stop if it cannot continue without the failing behavior.
   - Exception: the user explicitly asked to fix test failures (for example "fix the failures in run X" or "fix fingerprint abc123"). Then use `python -m testkit.failures prompt <fingerprint>` as the brief.
   - Running the tests again to confirm a failure is fine; changing things between runs is not.

3. **Cursor hook** `.cursor/hooks/test-failure-notice.py` on `postToolUse` with matcher `Shell`. The script filters for test commands (`pytest`, `regression.t4`, `regression.t5`, `ci-local.sh`, `git push`). If `test-runs/LATEST.json` shows a run that finished after the hook's last notice and has failures, it returns `additional_context` with the same instruction plus the run path. It fails open (an advisory hook must never block work) and keeps its last-notified run id in `.cursor/hooks/.state/` (gitignored). The existing `pre-pr.py` hooks are untouched.

The gate behavior does not change: pytest still exits non-zero, `ci-local.sh` still fails, the pre-push hook still blocks the push. An agent that is blocked by a failing gate reports it; it does not bypass the gate (`--no-verify`) or fix the failure unless asked.

## 5.9.5 Using the ledger later: `python -m testkit.failures`

| Command | Does |
|---|---|
| `latest` | Failures of the newest run (or `--group` for a whole gate run), grouped by tier then area. |
| `open` | Distinct failures, by fingerprint, that have not passed since: a fingerprint is open until a later run's `outcomes.tsv.gz` shows its nodeid passing. Shows first seen, last seen, occurrence count, triage status. |
| `show <fingerprint or run:seq>` | The full record, including traceback and repro command. |
| `prompt <fingerprint>` | Prints a self-contained fix brief to stdout for a fix agent you launch on purpose: case id, tier, catalog "Expect" text, error, traceback, repro command, related files, and the rule "fix the code under test, not the assertion, unless the catalog Expect is wrong". |
| `mark <fingerprint> --status investigating\|fixed\|wontfix\|quarantined --note "..." [--link URL]` | Writes `triage.json`. `quarantined` must match a `quarantine` marker with an issue link and expiry (10.4). |
| `export --format md\|json` | Prints a triage report to stdout (for an issue or PR description). It does not write a file. |
| `prune` | Applies retention now. |

## 5.9.6 Tests for the ledger (tier 1)

`tests/unit/testkit/test_failure_ledger.py` (uses `pytester`) and `tests/unit/testkit/test_failures_cli.py`:

- A failing, an erroring, and a collection-erroring test each produce exactly one record with the right `phase` and `outcome`; passing and skipped tests produce none.
- With `-n 4`, records are not duplicated or interleaved, and `seq` is contiguous.
- The exit code with the plugin equals the exit code with `--no-ledger`, for green, red, and interrupted runs.
- A run killed mid-way leaves its failure lines; the next run marks it `incomplete`.
- Secrets planted in an assertion message, captured stdout, and a traceback local are scrubbed.
- A plugin exception (unwritable dir) prints one warning and does not change the run's result.
- `fingerprint` is stable across line-number and temp-path changes, and differs for different exception types.
- `open` closes a fingerprint once its nodeid passes; `mark` round-trips; `prompt` includes the catalog Expect text.
- The banner appears only when failures were recorded.
