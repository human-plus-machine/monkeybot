# 5.10 Test catalog document (`docs/testing.md`)

> Part of the [regression plan](../README.md). Section numbers (§5.9, §6.U, D12, …) are global across the plan; the README's section map says which file holds each one.


monkeyapp keeps one document, `monkeyapp/docs/testing.md`, that lists its test layers, commands and gates, harness architecture, authoring rules, and a catalog of every flow with an ID, the expected behavior, a priority, and the test file that covers it. `tests/harness/catalog.test.ts` parses that catalog and fails when a test cites an unknown ID, two files claim one ID, or a recorded test path does not exist. monkeybot gets the same document and the same enforcement.

**File:** `docs/testing.md` (new, created in Phase 0b). After Phase 6 it is the living source of truth for "what is tested where". Section 6 of this plan (`reference/06-coverage/`) is the seed it is generated from; this plan is not updated afterwards.

**Outline** (mirrors monkeyapp's headings so both repos read the same way):

1. **Test tiers.** One table: Tier | Command or location | Drives | Fakes | Target.

   | Tier | Command or location | Drives | Fakes | Target |
   |---|---|---|---|---|
   | T1 contract/unit | `uv run pytest tests` (`tests/unit/**`, `tests/contracts/**`) | one module, or a table across modules | `testkit` doubles | logic, contracts, schemas, goldens |
   | T2 scripted trajectory | `uv run pytest regression/t2` | real `loop.run`, real in-process gateway, realtime WS | scripted provider, fake clock, fake worker | harness behavior per turn |
   | T3 record/replay | `uv run pytest regression/t3` | real loop / gateway / provider adapters | recorded cassettes, golden SSE | drift against real model and SDK output |
   | T4 live | `uv run pytest regression --live --suite smoke` / `python -m regression.t4` | real gateway + real provider | fixture workspaces only | model + harness on real tasks |
   | T5 trials | `python -m regression.t5 --suite ... --trials N` | T4 scenarios × N | none | pass rate vs keyed baseline |

2. **Commands and gates.** The commands from 5.6 and the gate table: pre-commit, pre-push (`ci-local.sh`), `ci.yml`, `storage-parity`, `cassette-staleness`, `live-smoke`, `live-trials` (section 9), with what each runs and what blocks.
3. **Harness architecture.** One line per `testkit` module and per `regression/drivers` module (sections 4.2, 4.4), and the ordering rules (for example: install the fake clock before importing the scheduler engine; settle hooks before asserting).
4. **Authoring rules.** The placement rule from 4.3; one case per scenario file named by its slug; assert on resulting state first; deterministic only (fake clock, port 0, fixed ids); "a failing new test is evidence to diagnose, not a reason to weaken the expected outcome" (same wording as monkeyapp); when intended behavior changes, update the catalog Expect cell, then the test, in the same change.
5. **Failures and the ledger.** The agent policy and the triage workflow from 5.9 (this is the section the banner and the agent rule point to).
6. **Catalog pairing.** What the pairing test enforces (below), and that the `## 8.` / `## 9.` headings and table shape must stay stable for the parser.
7. **Backfill rationale.** Bug-fix commits and the case that now guards each one, or why it cannot be tested at the current HEAD (same as monkeyapp §7). Filled from section 10.1's `regression_of:` fields.
8. **Case catalog.** One `###` subsection per area, in the section 6 order (Turn loop `LOOP`, Context `CTX`, Hooks `HOOK`, File tools `FILE`, Shell `SHELL`, Policy `POL`, Coding `CODE`, Attachments `ATT`, Computer use `COMP`, Subagents `SUB`, Verifier `VER`, Scheduler `SCHED`, Skills `SKILL`, MCP `MCP`, Web `WEB`, Memory `MEM`, Persistence `STORE`, Config `CFG`, Todo `TODO`, Providers `PROV`, Gateway `GW`, Realtime `RT`, Ops `OPS`). Each subsection is a table:

   | ID | Case | Expect | Tier | Pri | Origin | Test |
   |---|---|---|---|---|---|---|
   | T2-LOOP-07 | Doom loop on identical reads | three identical `read_file` calls trip `doom_loop`; the next request has no tools; a recovery note is in the system text | T2 | P0 | `core/runtime/doom_loop.py` | `regression/t2/loop/scenarios/loop/doom_identical_read.yaml` |

   - **Expect** is the behavior spec in plain words, taken from the section 6 "Asserts" column. It is what `catalog_expect` in a ledger record copies.
   - **Pri:** P0 = a regression here means the harness is broken or unsafe (loop guards, file/shell/policy enforcement, secret egress, persistence, the SSE contract, provider streaming); P1 = a feature is broken; P2 = polish or rarely used paths. Initial defaults per area: `LOOP`, `FILE`, `SHELL`, `POL`, `HOOK`, `STORE`, `PROV`, `GW` = P0; `CTX`, `CODE`, `ATT`, `SUB`, `VER`, `SCHED`, `SKILL`, `MCP`, `MEM`, `CFG`, `TODO`, `RT` = P1; `COMP`, `WEB`, `OPS` = P2. Individual rows are raised or lowered during review.
   - **Origin:** the source module, or the commit/PR for a bug-fix case.
   - **Test:** the file path once the case exists; empty until then. Empty rows are counted as uncovered, not failures (same as monkeyapp).
   - Existing unit tests without a case ID are listed per area in a short "Existing unit coverage" line (folder paths), not row by row, so the catalog stays about behaviors.
9. **Deferred coverage.** What is intentionally not covered yet and why (macOS-only computer tools in CI, Postgres/Firestore outside the optional job, browser-mcp internals, production traces, performance).

**Pairing enforcement:** `tests/contracts/test_catalog_pairing.py` (tier 1, runs on every push) parses `docs/testing.md` §8 and every test's case ID (YAML `case:` key; `@pytest.mark.case(...)` on Python tests). It fails when:

- a test cites an ID that is not in the catalog;
- an ID is cited by a file that is not listed in that row's Test cell (one row may list several files, e.g. the `_positive` / `_negative` pair of `T2-VER-01`);
- a Test cell names a path that does not exist;
- an ID appears twice in the catalog, or an ID's tier prefix disagrees with the folder it lives in (goal 6).

It prints, but does not fail on, the count of uncovered rows per area and tier; that number is the progress meter for Phases 1–5.
