# 5.3 Assertion engine (`regression/schema/assertions.py`)

> Part of the [regression plan](../README.md). Section numbers (§5.9, §6.U, D12, …) are global across the plan; the README's section map says which file holds each one.


One engine; a key that does not make sense in the scenario's mode is rejected at load time.

## 5.3.1 Assertion keys

| Key | Modes | Semantics |
|---|---|---|
| `turn_completed`, `no_errors` | all | As today. |
| `error_contains` | all | Some `Error.error` contains the string. |
| `events_sequence` | scripted, replay | Ordered subsequence of event `type`s (with optional field matchers). |
| `events_absent` | all | Event types that must not appear. |
| `event_fields` | all | `{type: {field: value or regex}}` for at least one event of that type. |
| `interventions` | scripted, replay | Exact ordered list of `HarnessIntervention.intervention` (optionally `detail`). Today it is "each appears", unordered. Keep `interventions_include` for the loose form. |
| `provider_calls` | scripted, replay | Exact `stream()` count. |
| `provider_request` | scripted, replay | Matchers on the Nth request: `tools_include`, `tools_exclude`, `tools_empty`, `system_contains`, `system_not_contains`, `messages_contain`, `no_vertex_google_search`. |
| `required_tools` | all | Exact tool names that must be called at least once. |
| `forbidden_tools` | all | Tool names that must never be called. |
| `tool_categories_used` | all | **Subset** check (today it is an intersection, so listing `read` + `write` passes when only `read` ran). |
| `tool_calls` | all | `min`, `max`, per-name counts. |
| `tool_error_codes` | all | `details.code` values that must appear. |
| `tool_error_codes_absent` | all | Codes that must not appear. |
| `max_tool_errors` | all | Unresolved errors. Forgiveness rule tightened: an error is resolved only by a later success of the same tool **on the same canonical target** (path/command), not just the same name. |
| `workspace_file_contains`, `workspace_file_absent`, `workspace_unchanged`, `workspace_command_passes` | all | As today; one implementation, one timeout (180 s). |
| `files_not_touched` | all | fnmatch globs against path-like args. |
| `verified_before_final` | all | As today. |
| `history` | scripted, replay | Matchers on stored rows: row count, roles, tool pairs intact, summary row present, row ids preserved, no repaired rows persisted. |
| `store` | scripted, replay | Matchers on backend state: outbox rows, usage rows, loop rows, goal rows, branch rows. |
| `memory_injected` | all | Now checks content (`contains:`), not just "non-empty". |
| `verdicts` | all | `min`, `max`, `status_in`, `severity_max`, `signals_include`, `signals_exclude`. |
| `subagent` | all | `started`, `completed_ok`, `artifact_exists`, `progress_jsonl_lines_min`, `output_json_present`. |
| `sse` | gateway driver, live | `frames_have_ids`, `active_requests_once`, `one_turn_complete_per_request`, `replay_from(last_event_id)` expectations. |
| `response_contains` (any), `response_contains_all`, `response_not_contains`, `response_regex`, `final_text_regex` | all | `response_contains` keeps OR semantics but is renamed in docs to make it explicit; `_all` is the AND form. |
| `metrics`, `min_score` | live | LLM judge. Optional. |
| `max_latency_ms`, `max_input_tokens`, `max_output_tokens`, `max_cost_usd` | live | Budgets. |
| `verifier_on`, `verifier_off` | live | Merged when `EVAL_VERIFIER_MODE` matches. **Load error** if these blocks exist and the mode is unset (today the checks silently vanish). |

## 5.3.2 Global invariants (`regression/schema/invariants.py`)

Run after every T2 and T3 trajectory, regardless of the scenario's own assertions. A scenario can opt out of one with `invariants_skip: [name]` and a reason.

1. Exactly one `TurnComplete` per run, and it is the last event.
2. Every `ToolCallStarted` with a `call_id` has exactly one `ToolCallResult` with the same `call_id`.
3. No tool executes after the cancel event fires.
4. Stored history has no orphan `ToolRequest` / `ToolResponse` pairs.
5. No `HarnessIntervention` on the SSE wire (gateway driver).
6. Every serialized event validates against `tests/contracts/goldens/sse/schema.json` (gateway driver).
7. Strict `ScriptedProvider`: every scripted call was consumed (no leftover script) unless `script_partial: true`.
8. The turn lock is released at the end (gateway driver: a second `/reply` is not 409).
