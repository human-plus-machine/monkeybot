# 5.5 Cassettes

> Part of the [regression plan](../README.md). Section numbers (§5.9, §6.U, D12, …) are global across the plan; the README's section map says which file holds each one.


## 5.5.1 T3a trajectory cassette

One JSON file per recorded run.

```json
{
  "schema_version": 1,
  "kind": "trajectory",
  "recorded_at": "2026-10-25T15:00:00Z",
  "harness_commit": "<sha>",
  "provider": "ollama-cloud",
  "model": "glm-5.3-flash",
  "tool_schema_digest": "<sha256 of sorted tool names + input schemas>",
  "prompt_digest": "<sha256 of stable system prefix>",
  "source_transcript": "<relative path or null>",
  "scenario": "coding/fix_failing_test",
  "calls": [
    {
      "index": 0,
      "request": {"tool_names": ["read_file", "..."], "message_count": 2},
      "events": [
        {"type": "tool_call", "call_id": "c1", "name": "read_file", "args": {"path": "calc/ops.py"}},
        {"type": "usage", "input_tokens": 1234, "output_tokens": 56},
        {"type": "done"}
      ]
    }
  ],
  "tool_results": {"c1": "<optional recorded result for executor: recording replays>"},
  "classifier": [
    {"intent": "new_goal", "constraints": [{"kind": "path_glob", "pattern": "DONE.txt", "verbatim": "Create DONE.txt"}], "done_when": ["DONE.txt"]}
  ],
  "judge": [
    {"mode": "valid", "body": "{\"status\":\"on_track\",\"severity\":\"none\",\"confidence\":0.75,\"rationale\":\"\"}", "hang_s": 0, "input_tokens": 0, "output_tokens": 40}
  ]
}
```

Sources:

- `t3/tools/from_transcript.py` converts `transcript.ndjson` (resolving `text_seq` / `content_seq` / `result_seq` / `base_seq`+`diff` pointers first) into a cassette: each `ProviderResponse` becomes `thinking` + `tool_call`s + one `text` + `usage` + `done`. Each `VerifierVerdict` becomes one `judge` completion (status, severity, confidence, rationale; `judge_tokens` is stored as `output_tokens`). `classifier` rows are read from the session SQLite goal ledger (`--ledger`), one human row per message, because those decisions are not provider calls. Replay feeds `classifier` to `ScriptedClassifier` and `judge` to `ScriptedJudge`. Both lists are empty when the run has neither.
- Optional `RecordingProvider` wrapper in the T4 agent for runs where the exact request body matters.

Replay rules:

- **Strict replay** (default): if a recorded tool name is not in the current tool list, or a recorded arg key is no longer in that tool's schema, fail with `cassette_stale: tool <name> changed`. Re-record.
- If `tool_schema_digest` or `prompt_digest` differ, warn (the model might have chosen differently), do not fail. A test that should fail on prompt changes uses the T1 harness-prompt golden.
- Executor is `real` by default (fixture workspace), so a harness change that breaks tool behavior on realistic args fails the replay.

## 5.5.2 T3b provider wire cassette

`t3/wire/<provider>/<scenario>.json`:

```json
{
  "schema_version": 1,
  "kind": "wire",
  "provider": "anthropic",
  "sdk": {"anthropic": "0.x.y"},
  "recorded_at": "...",
  "request": {"method": "POST", "path": "/v1/messages", "body": {"...": "scrubbed"}},
  "response": {"status": 200, "headers": {"content-type": "text/event-stream"}, "chunks": ["event: message_start\ndata: {...}\n\n", "..."]},
  "expected_events": [{"type": "text", "text": "..."}, {"type": "done", "truncated": false}]
}
```

- Replay preferred path: `httpx.MockTransport` mounted as the SDK's `http_client` (OpenAI, Anthropic, and every OpenAI-compat adapter). The installed SDK parses real frames.
- Second-choice path where a transport mock is impractical (google-genai, boto3 Converse): store the raw chunk JSON and run it through the SDK's own model/parser (`ChatCompletionChunk.model_validate`, Anthropic event union, botocore event parser) before the adapter iterator. Do not stub `iter_openai_compat_stream`; that skips the code under test.
- Scrub before write: `Authorization`, `x-api-key`, `x-goog-api-key`, any `sk-` / `nvapi-` / bearer substring, project ids.
- Staleness: `t3/tools/check_staleness.py` fails when the installed SDK version differs from the cassette's `sdk` field and no re-record exists. Re-record only with `MONKEYBOT_RECORD_CASSETTES=1` (manual; lockfile PRs are the reminder).
- The request body is asserted too, so converter drift is caught separately from parser drift.

## 5.5.3 T3c golden SSE streams

`t3/sse/<name>.sse` holds the exact framed bytes for a scripted turn through the gateway driver with a fixed clock and fixed ids:

```text
id: 1
data: {"type":"Thinking","request_id":"r1"}

id: 2
data: {"type":"AssistantDelta","request_id":"r1","delta":"hi"}

id: 3
data: {"type":"TurnComplete","request_id":"r1","usage":{"input_tokens":0,"output_tokens":0,"cached_tokens":0,"cache_read_tokens":0,"cache_creation_tokens":0,"cost_usd":0.0,"duration_ms":0,"estimated_prompt_tokens":0}}

data: {"type":"ActiveRequests","request_ids":[]}

: ping 1
```

`tests/contracts/goldens/sse/schema.json` is generated from `event_to_json` over every `AgentEvent` variant (including omitted-field cases) by `uv run pytest tests/contracts/test_sse_schema.py --update-golden`. It lives with tier 1 because it is a contract of the serializer; the `.sse` streams stay in `regression/t3/sse/` because they need the gateway driver. It is the cross-repo contract; monkeyapp vendors it (section 6.U).

Normalization before byte compare: `duration_ms`, `trace_id`, timestamps, and generated ids are replaced with fixed tokens.
