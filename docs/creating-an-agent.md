# Creating an Agent

This guide walks through every decision you'll make when building a monkey-bot agent — from picking a model to wiring up memory, skills, and scheduled jobs.

---

## Overview

A monkey-bot agent has five main components:

```
1. bot.yaml          — Non-secret configuration
2. .env              — Local secrets (dev only)
3. src/main.py       — Agent wiring + FastAPI server
4. skills/           — Custom tools and capabilities
5. src/job_handlers.py — Background job logic
```

Everything else — the gateway, memory system, scheduler, checkpointing, PII filtering — is provided by the framework.

---

## Step 1: Configure Your Bot

### bot.yaml

This is the single source of truth for your bot's non-secret configuration. It ships with your code.

```yaml
# bot.yaml
agent:
  name: my-bot          # Used in logs, metadata, and heartbeat reports
  skills_dir: ./skills  # Where the framework looks for SKILL.md files

model:
  provider: google_vertexai   # google_vertexai | openai | anthropic | vertex_anthropic
  name: gemini-2.5-flash      # Model name for the chosen provider
  temperature: 0.7            # 0.0 = deterministic, 1.0 = creative
  max_tokens: 8192            # Max output tokens per response

server:
  port: 8080
  log_level: INFO             # DEBUG | INFO | WARNING | ERROR

gateway:
  allowed_users:              # Only these emails can interact with the bot
    - alice@company.com
    - bob@company.com
  chat_format: workspace_addon  # workspace_addon | legacy

memory:
  dir: ./data/memory          # Local memory directory
  backend: local              # local (dev) | gcs (production)
  bucket: my-bot-memory       # GCS bucket name (required if backend: gcs)

scheduler:
  storage: json               # json (dev/single-instance) | firestore (production/multi-instance)
  cadence: "* * * * *"        # How often Cloud Scheduler calls /cron/tick
  timezone: America/New_York

secrets:
  provider: env               # env (dev) | gcp_secret_manager (production)

gcp:
  project_id: my-gcp-project
  location: us-central1
```

**Priority chain:** `environment variables > bot.yaml > framework defaults`

Any value in `bot.yaml` can be overridden by setting the corresponding environment variable (see [Configuration Reference](configuration.md)).

## Step 2: Define Your System Prompt

The system prompt tells the agent who it is and what it does. monkey-bot uses a **3-layer prompt system**:

| Layer | Source | Purpose |
|---|---|---|
| Layer 0 | `SOUL.md`, `IDENTITY.md`, `USER.md`, `INDEX.md` | Agent identity, personality, memory index |
| Layer 1 | Auto-generated by framework | Skills manifest, memory instructions, tool usage |
| Layer 2 | Framework base | Generic agent capabilities description |
| Layer 3 | Your `user_system_prompt` | Your domain-specific instructions |

You only need to write **Layer 3** — your domain instructions. The framework handles the rest.

### Pass it inline

```python
agent = build_deep_agent(
    model=model,
    tools=tools,
    user_system_prompt="""You are a customer support agent for Acme Corp.

Your responsibilities:
- Answer questions about products and pricing
- Help users troubleshoot common issues
- Escalate complex issues by scheduling a follow-up

Always be polite, concise, and solution-focused.
Current product catalog: https://acme.example.com/products
""",
)
```

### Load from a file (recommended for long prompts)

```python
from emonk.core.config import get_system_prompt

# Reads from the path configured in SYSTEM_PROMPT_FILE env var
prompt = get_system_prompt()

agent = build_deep_agent(
    model=model,
    tools=tools,
    user_system_prompt=prompt,
)
```

### Identity files (advanced)

For persistent agent personality, create markdown files in your memory directory:

```
data/memory/
├── SOUL.md       # Core personality, values, communication style
├── IDENTITY.md   # Role, responsibilities, operational context
├── USER.md       # Known preferences about the primary user
└── INDEX.md      # Map of what the agent has stored in memory
```

**Example `SOUL.md`:**
```markdown
I am precise, direct, and curious. I avoid corporate speak.
I prefer bullet points over paragraphs when listing items.
I ask clarifying questions rather than guessing intent.
When I'm uncertain, I say so.
```

**Example `IDENTITY.md`:**
```markdown
I am the engineering assistant for the Platform team at Acme Corp.
I have access to the codebase via the file-ops skill and can run diagnostics.
My primary users are software engineers who need fast, accurate technical help.
```

Token budget guidance:
- `SOUL.md` — keep under 500 tokens
- `IDENTITY.md` — keep under 800 tokens
- `INDEX.md` — keep under 1000 tokens

## Step 3: Add Tools

Tools are LangChain `@tool`-decorated functions passed directly to `build_deep_agent()`.

### Basic tool

```python
from langchain_core.tools import tool

@tool
def lookup_order(order_id: str) -> str:
    """Look up the status of an order by its ID.
    
    Args:
        order_id: The order ID (format: ORD-XXXXXX)
    
    Returns:
        Order status and estimated delivery date
    """
    # Your actual logic here
    return f"Order {order_id}: Shipped, arrives Thursday"
```

### Async tool (recommended for I/O)

```python
@tool
async def fetch_customer_data(customer_email: str) -> str:
    """Fetch customer account data from the CRM.
    
    Args:
        customer_email: Customer's email address
    
    Returns:
        Customer tier, account status, and recent orders
    """
    async with httpx.AsyncClient() as client:
        response = await client.get(
            f"https://api.crm.example.com/customers/{customer_email}",
            headers={"Authorization": f"Bearer {os.getenv('CRM_API_KEY')}"},
        )
    return response.json()
```

### Pass tools to the agent

```python
agent = build_deep_agent(
    model=model,
    tools=[lookup_order, fetch_customer_data],
    user_system_prompt=prompt,
    scheduler=scheduler,
)
```

**Auto-added tools:** When you pass a `scheduler`, the framework automatically adds `schedule_task`. When you pass a `store`, it automatically adds `search_memory`. Do not add these manually.

## Step 4: Add Skills

Skills are reusable capabilities stored as files in `./skills/`. Unlike tools (which are in-memory Python functions), skills are discovered from the filesystem and their code is read by the agent before execution.

See the [Skills System](skills.md) guide for full details. Quick summary:

```
skills/
└── my-skill/
    ├── SKILL.md          # Metadata + description
    └── my_skill.py       # The actual Python tool
```

Skills are auto-discovered when you set `skills_dir` in `bot.yaml`. You do not need to import or register them manually.

## Step 4b: Add Subagents (Optional)

Subagents let you partition a large skill set across specialised workers, each with its own focused context window.  The orchestrator delegates to them via the built-in `task` tool.  All agents share the same filesystem and shell.

**When to add subagents:**
- Your agent has 10+ skills and you notice the model losing focus.
- Different skill groups serve clearly different specialisations (research vs. writing vs. analytics).
- You want different models for different roles (e.g. fast model for analytics, capable model for writing).

**When to skip:**
- Your agent has a small, cohesive skill set (< ~8 skills).
- All skills are tightly coupled to a single domain.

**Quick setup:**

1. Organise skills into per-subagent subdirectories:

```
skills/content-intelligence/
├── research-domain-content/
│   ├── SKILL.md
│   └── research_domain_content.py
└── extract-content-patterns/
    ├── SKILL.md
    └── extract_content_patterns.py
```

2. Add the `subagents:` section to `bot.yaml`:

```yaml
subagents:
  - name: content-intel
    description: >
      Research top-performing content and extract engagement patterns.
    skills:
      - ./skills/content-intelligence/
```

3. That's it.  The framework wires `SkillsMiddleware` per subagent and adds the `task` tool to the orchestrator automatically.

See the [Subagents](subagents.md) guide for the full configuration reference, skills layout conventions, and prompt-writing guidance.

## Step 5: Wire Up Memory (Optional)

Enable GCS-backed memory for production deployments where you need:
- Session summaries that persist across restarts
- Cross-conversation recall (`search_memory` tool)
- Memory sync between container instances

```python
from emonk.core.store import GCSStore

# Create the store
store = GCSStore(
    bucket_name="my-bot-memory",
    project_id="my-gcp-project",
)

# Pass to build_deep_agent — automatically adds search_memory tool
agent = build_deep_agent(
    model=model,
    tools=tools,
    user_system_prompt=prompt,
    scheduler=scheduler,
    store=store,        # Enables session summaries + search_memory tool
)
```

After 5+ messages in a conversation, the framework automatically:
1. Summarizes the session
2. Extracts key topics
3. Writes a summary doc to `("shared", "session_summaries")` namespace in GCS
4. Exposes it via `search_memory` for future recall

See [Memory System](memory.md) for deeper details.

## Step 6: Wire Up the Scheduler

The scheduler lets your agent create and execute background jobs — reports, reminders, alerts, anything that needs to run at a future time.

### Set up the scheduler

```python
from emonk.core.scheduler import CronScheduler, create_storage

storage = create_storage()  # JSON (dev) or Firestore (production) based on bot.yaml
scheduler = CronScheduler(storage=storage)
```

### Register job handlers

```python
# src/job_handlers.py
import httpx
import os

async def handle_weekly_report(job: dict) -> None:
    """Execute a weekly report job."""
    payload = job.get("payload", {})
    user_email = payload.get("user_email")
    space_name = payload.get("space_name")
    
    # Generate the report
    report = f"Weekly summary for {user_email}:\n- 42 requests processed\n- 0 errors"
    
    # Post to Google Chat
    webhook_url = os.getenv("GOOGLE_CHAT_WEBHOOK")
    if webhook_url and space_name:
        async with httpx.AsyncClient() as client:
            await client.post(webhook_url, json={"text": report})

def register_handlers(scheduler: CronScheduler) -> None:
    scheduler.register_handler("weekly_report", handle_weekly_report)
```

### Connect it all in main.py

```python
from src.job_handlers import register_handlers

agent = build_deep_agent(
    model=model,
    tools=tools,
    user_system_prompt=prompt,
    scheduler=scheduler,
)

# IMPORTANT: attach scheduler to agent so /cron/tick can find it
agent.scheduler = scheduler

# Register handlers AFTER agent is built
register_handlers(scheduler)
```

### How the agent schedules a job

Your agent has the `schedule_task` tool available. Users (or your system prompt) can trigger it:

```
User: "Schedule a weekly report for every Monday at 9am"

Agent calls: schedule_task(
    job_type="weekly_report",
    schedule_at_iso="2026-03-23T09:00:00-05:00",
    payload={
        "user_email": "alice@company.com",
        "space_name": "spaces/ABC123"
    }
)
```

When Cloud Scheduler calls `/cron/tick` at 9am Monday, the job executes and `handle_weekly_report` runs.

See [Scheduler & Jobs](scheduler.md) for full details.

## Step 7: Build the FastAPI Server

Wire everything into a FastAPI app that monkey-bot's gateway will serve.

```python
# src/main.py
import os
import uvicorn
from contextlib import asynccontextmanager
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

from emonk.core.config import load_secrets, get_model
from emonk.core.deepagent import build_deep_agent
from emonk.core.scheduler import CronScheduler, create_storage
from emonk.gateway.server import create_gateway  # Optional: use the built-in gateway

from src.job_handlers import register_handlers

# Load config and secrets at module import
load_secrets()

def create_agent():
    model = get_model()
    storage = create_storage()
    scheduler = CronScheduler(storage=storage)
    
    agent = build_deep_agent(
        model=model,
        tools=[],  # Add your tools here
        user_system_prompt="You are a helpful assistant.",
        scheduler=scheduler,
    )
    agent.scheduler = scheduler
    register_handlers(scheduler)
    return agent, scheduler

agent, scheduler = create_agent()

@asynccontextmanager
async def lifespan(app: FastAPI):
    await scheduler.start()
    # If using GCS memory sync, start it here:
    # if hasattr(agent, 'fs_sync') and agent.fs_sync:
    #     await agent.fs_sync.start()
    yield
    await scheduler.stop()

app = FastAPI(title="my-bot", lifespan=lifespan)

@app.get("/health")
async def health():
    return {"status": "healthy", "agent": os.getenv("AGENT_NAME", "my-bot")}

@app.post("/run")
async def run(request: Request):
    """Direct API endpoint — for programmatic access."""
    body = await request.json()
    message = body.get("message", "")
    user_id = body.get("user_id", "anonymous")
    
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": message}]},
        config={"configurable": {"thread_id": user_id}},
    )
    return {"response": result["messages"][-1].content}

@app.post("/webhook")
async def webhook(request: Request):
    """Google Chat Workspace Add-on webhook."""
    raw_payload = await request.json()
    
    # Extract message context
    user_email = None
    space_name = None
    message_text = ""
    
    if "chat" in raw_payload:
        chat = raw_payload["chat"]
        message_payload = chat.get("messagePayload", {})
        user_email = message_payload.get("message", {}).get("sender", {}).get("email")
        space_name = message_payload.get("space", {}).get("name")
        message_text = message_payload.get("message", {}).get("argumentText", "").strip()
    
    if not user_email or user_email not in os.getenv("ALLOWED_USERS", "").split(","):
        return JSONResponse({"text": "Unauthorized"}, status_code=403)
    
    # Inject system context so agent knows who's asking and where to send results
    enhanced_message = (
        f"{message_text}\n"
        f"[System context: user_email={user_email}, space_name={space_name}]"
    )
    
    result = await agent.ainvoke(
        {"messages": [{"role": "user", "content": enhanced_message}]},
        config={"configurable": {"thread_id": user_email}},
    )
    
    response_text = result["messages"][-1].content[:4000]  # Google Chat limit
    
    return {
        "hostAppDataAction": {
            "chatDataAction": {
                "createMessageAction": {
                    "message": {"text": response_text}
                }
            }
        }
    }

@app.post("/cron/tick")
async def cron_tick(request: Request):
    """Called by Cloud Scheduler every minute."""
    # Optional: validate cron secret
    cron_secret = os.getenv("CRON_SECRET")
    if cron_secret:
        auth = request.headers.get("Authorization", "")
        if auth != f"Bearer {cron_secret}":
            return JSONResponse({"error": "Unauthorized"}, status_code=401)
    
    if not hasattr(agent, "scheduler") or not agent.scheduler:
        return JSONResponse({"error": "Scheduler not initialized"}, status_code=500)
    
    result = await agent.scheduler.run_tick()
    return {"status": "ok", "result": result}

if __name__ == "__main__":
    uvicorn.run("src.main:app", host="0.0.0.0", port=int(os.getenv("PORT", 8080)))
```

## Step 8: Write a Dockerfile

```dockerfile
FROM python:3.12-slim

WORKDIR /app

# Install dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy application
COPY . .

# Create memory directory
RUN mkdir -p data/memory/scheduler

EXPOSE 8080

CMD ["python", "-m", "src.main"]
```

## Checklist

Before deploying to production:

- [ ] `bot.yaml` has your agent name and correct model
- [ ] `allowed_users` is set to only authorized emails
- [ ] All tools have clear docstrings (the LLM reads these to decide when to call them)
- [ ] Job handlers are registered with `register_handlers(scheduler)`
- [ ] `agent.scheduler = scheduler` is set before the app starts
- [ ] `secrets.provider` is set to `gcp_secret_manager` in `bot.yaml` (not `env`)
- [ ] `memory.backend` is set to `gcs` in `bot.yaml` (not `local`)
- [ ] `scheduler.storage` is set to `firestore` in `bot.yaml` (not `json`)
- [ ] Dockerfile is present and builds successfully
- [ ] Health endpoint returns 200
