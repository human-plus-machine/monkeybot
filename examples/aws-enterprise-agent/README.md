# AWS Enterprise Reference Agent

Drop-in reference deployment of the Agent Harness onto AWS Bedrock
AgentCore. This directory ships everything an enterprise operator needs to
stand up the seven-pillar stack in ≤ 30 minutes against a clean AWS account.

## What you get

| Pillar              | Backend (shipped)               | Config knob                                  |
| ------------------- | ------------------------------- | -------------------------------------------- |
| Checkpointer        | `PostgresCheckpointer`          | `checkpointer.backend: postgres`             |
| Memory store        | `S3MemoryStore` (SSE-KMS)       | `memory_store.backend: s3`                   |
| Job storage         | `PostgresJobStorage`            | `job_storage.backend: postgres`              |
| Identity source     | `S3IdentitySource`              | `identity_source.backend: s3`                |
| Secret resolver     | Composite (AWS SM → Env)        | `secret_resolver.backend: composite`         |
| Model provider      | `BedrockProvider` (Claude 3.5)  | `model_provider.backend: bedrock`            |
| Run-package writer  | `S3RunPackageWriter`            | `observability.run_package.writer: s3`       |

## Prerequisites

1. **AWS CLI** configured with credentials that can provision RDS, S3, IAM,
   KMS, and Bedrock (`aws sts get-caller-identity` should succeed).
2. **Terraform** ≥ 1.5.
3. **Docker** ≥ 24 with BuildKit enabled.
4. A VPC with at least two private subnets across distinct AZs. Pass the VPC
   id, subnet ids, and route-table ids into Terraform via `TF_VAR_*`.
5. Bedrock model access granted for
   `anthropic.claude-3-5-sonnet-20241022-v2:0` in your region.

## 5-step quickstart

### 1. Provision the stack

```bash
cd terraform
terraform init
terraform apply \
  -var="project_name=my-ent" \
  -var="vpc_id=vpc-xxxxxxxxxxxx" \
  -var='private_subnet_ids=["subnet-aaa","subnet-bbb"]' \
  -var='route_table_ids=["rtb-xxx"]' \
  -var="bucket_name=my-ent-emonk-data" \
  -var="db_password=$(openssl rand -base64 24)"
```

Terraform outputs include `rds_endpoint`, `s3_bucket_name`, `kms_key_id`,
`iam_role_arn`, and `ckpt_dsn_secret_arn`. Keep them for the next step.

### 2. Populate Secrets Manager

Populate the `{project_name}/ckpt-dsn` secret with the Postgres DSN
Terraform printed (e.g.
`postgresql://emonk_admin:<password>@<rds_endpoint>/emonk_ckpt`). Bedrock
auth is handled entirely via the IAM role — no API keys required.

```bash
aws secretsmanager put-secret-value \
  --secret-id my-ent/ckpt-dsn \
  --secret-string "postgresql://emonk_admin:<PASSWORD>@<RDS_HOST>:5432/emonk_ckpt"
```

### 3. Regenerate the pinned lockfile

```bash
pip install pip-tools
pip-compile --generate-hashes \
  --output-file=requirements.lock.txt requirements.in
```

This step is **mandatory** — `Dockerfile.aws-enterprise` uses
`pip install --require-hashes`, so the image build fails fast until the
lockfile is populated for your platform.

### 4. Build the image

```bash
docker build -f Dockerfile.aws-enterprise -t aws-enterprise-agent:latest .
```

### 5. Run + smoke-test

```bash
docker run --rm \
  -e CKPT_DSN="postgresql://..." \
  -e S3_BUCKET="my-ent-emonk-data" \
  -e KMS_KEY_ID="$(terraform -chdir=terraform output -raw kms_key_id)" \
  -e AWS_REGION="us-east-1" \
  -e HARNESS_ENABLE_AWS_SMOKE=1 \
  -e EMONK_ADMIN_TOKEN="$(openssl rand -hex 32)" \
  -p 8080:8080 \
  aws-enterprise-agent:latest

# In another shell:
curl -s http://localhost:8080/agentcore/ping
curl -s -H "X-Admin-Token: $EMONK_ADMIN_TOKEN" \
  http://localhost:8080/harness/aws/smoke | jq
```

All six probes (`postgres`, `s3`, `secrets_manager`, `bedrock`, `kms`,
`sts`) should report `reachable: true`.

## Gotchas

- **Bedrock model access** is a separate opt-in flow in the AWS console; the
  Terraform module cannot grant it for you.
- **RDS deletion protection** is enabled by default. Disable it before
  `terraform destroy` in sandbox accounts.
- **`HARNESS_PLUGINS_FROM_ENTRY_POINTS=0`** is baked into the Dockerfile —
  the runtime resolves registries deterministically from the installed
  builtins only. Do not set this to `1` in production.
- **`HARNESS_ENABLE_AWS_SMOKE=1`** opens the `/harness/aws/smoke` endpoint.
  Keep it disabled in general production; enable only for verification
  windows.
